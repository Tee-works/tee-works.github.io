A governed claims platform from messy hospital files

A health insurer receives claims from partner hospitals that each send data their own way, plus a telemedicine API and monthly membership snapshots full of personal data. The platform has to turn that into one trustworthy model, and keep member identities away from people who do not need them.

Type
Independent project
Data
Synthetic, seeded
Build
About 20 seconds locally
Focus
Modelling, privacy, governance

01The problem

Three hospital house formats: ISO dates, dd/mm/yyyy or yyyymmdd; amounts as decimals, naira strings or integer kobo; rejected claims coming back as resubmissions under the same reference. Telemedicine pages overlap, so 40 consultations arrive twice. Membership snapshots carry names, phone numbers and dates of birth.

02What I built

  • Ingestion of 299 monthly files from 15 hospitals through one mapping file per format, so a new hospital on an existing format is a row of config, not new code.
  • Data contracts with TrueSet on every source: failing rows go to quarantine with their reasons. Exactly the 40 broken rows are quarantined and nothing else, and a test proves it. Loads are idempotent by file hash.
  • 18 dbt models with 49 data tests: latest resubmission wins, member plan history as a slowly changing dimension, and enforced contracts on the tables dashboards depend on.
  • Pseudonymised analytics: members appear only as a salted key, and a test fails the build if any analytics column looks like personal data. Governance rules run as OPA policies against what was built.
  • A reconciliation test checks every naira of approved claims lands in the loss-ratio mart. The AWS target is described in Terraform with least-privilege access.

03The result

The loss ratio ranges from 0.39 to 1.94 by employer: the spread that drives corporate renewal pricing, now computed from tested, pseudonymised tables.

The whole platform builds locally in about 20 seconds, so every change is checked end to end.
