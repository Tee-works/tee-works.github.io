Payments change data capture that keeps every state

Batch extracts that ask for rows updated since the last run see each payment once. A payment that goes pending, failed, then successful between runs looks successful, and hard deletes vanish. For a payments ledger that is not good enough.

Type
Independent project
Pattern
Change data capture
Runs on
Docker or Kubernetes
Focus
Streaming, reconciliation

01The problem

A payments team needs every state a payment passed through, a warehouse that matches the source on money (not just on row counts), and a pipeline that can crash and replay without counting anything twice.

02What I built

  • Debezium reads every insert, status change and delete from the MySQL binlog into Kafka; a JDBC sink upserts the current state into a Postgres warehouse and follows schema changes.
  • A Python consumer reads the same stream into an append-only status history. Writes are idempotent: each row is keyed by its binlog position, and Kafka offsets are committed only after the database transaction, so a crash and replay inserts nothing twice.
  • Lifecycle rules flag changes that should never happen, such as failed to success or an amount edited after settlement. They are recorded, not dropped; only unparseable messages go to a dead-letter topic with the reason.
  • A daily Airflow job reconciles source and warehouse by count and by amount for each day and status, because matching row counts can hide a truncated amount.
  • Runs locally in Docker or on Kubernetes with Strimzi, a Helm chart and Terraform. CI runs lint, unit tests, helm lint, terraform validate, a DAG import check and a full end-to-end test on every push.
