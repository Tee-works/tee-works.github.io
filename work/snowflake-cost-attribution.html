Who’s burning the Snowflake bill?

When analytics is decentralised, dozens of people and service users run queries on shared Snowflake warehouses. The bill arrives per warehouse, not per person, so when it jumps nobody knows who to talk to. This project builds query-level cost attribution and team showback, on synthetic data.

Type
Independent project
Data
Synthetic, seeded
Scale
9,451 queries, 4 warehouses
Focus
Cost attribution, showback

01The problem

Snowflake bills for the time a warehouse is running, including the idle tail before it auto-suspends. Snowflake’s own QUERY_ATTRIBUTION_HISTORY leaves idle time out, so attributing cost per user alone can hide most of the bill.

And showback that people cannot reconcile to the bill gets argued with, not acted on. Every credit has to land somewhere, and the total has to match the invoice.

The generator simulates four weeks of ACCOUNT_USAGE: 9,451 queries from 30 data champions plus Airflow, Airbyte and Looker service users, across four warehouses, with the hourly metering those queries would bill. It plants four cost problems: a dashboard refreshing every 15 minutes all night on a LARGE warehouse, one person re-running an unfiltered scan every working hour, an ad-hoc warehouse with a one-hour auto-suspend, and a 20x week-over-week spike for one team.

02What I built

  • Query x hour slices, so a long query is split across the clock hours it ran in.
  • Warehouse busy time as the union of query time, so concurrent queries are not double counted. Idle time is billed running time minus busy time.
  • Query cost: each hour’s active credits are shared by its queries in proportion to execution seconds, and idle credits stay with the warehouse instead of being smeared across users.
  • Showback by user, team and workload, in credits and USD, with alerts for a team week-over-week spike, a warehouse idle share over 25%, and any workload over 10% of spend.
  • Five checks run on every build: the reconciliation to the bill, one row per query, every query costed, no negative or null costs, and busy time never more than running time. Four tests check the checks, including that the planted problems are flagged and that a rebuild gives the same numbers.
  • The column names match Snowflake’s, so the SQL runs there with only the source names changed. An Airflow DAG sketches the daily job; it is illustrative and not run in the tests.

03The result

of metered credits were idle warehouse time (3,285 of 4,103)
1e-6
attributed plus idle credits equal the bill, to this tolerance
86%

The biggest cost was not anyone’s SQL. The overnight dashboard refresh kept the BI warehouse awake (86% idle), and the ad-hoc warehouse’s one-hour auto-suspend did the same (79% idle). The fixes are a shorter auto-suspend and a less frequent refresh, not asking 30 people to write cheaper queries.

All three planted user-level problems were caught: the dashboard, the hourly unfiltered scan and the team spike.
