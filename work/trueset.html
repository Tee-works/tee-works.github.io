TrueSet: open-source data quality and reconciliation

Teams rewrite the same data checks for every engine they use: once in pandas for a notebook, again in SQL for the warehouse, again for the next tool. TrueSet lets you write a check once and run it unchanged where the data lives.

Type
Open-source library
Licence
Apache-2.0
Install
pip install trueset
Focus
Checks, reconciliation

01The problem

When the same rule exists in three places, the three copies drift apart, and nobody can say which one is the real definition. Failing rows also tend to be counted rather than kept, so nobody can fix them.

02What I built

  • Checks run on pandas, DuckDB or a warehouse as pushed-down SQL.
  • Cross-system reconciliation, so a load can be proven against its source.
  • Failing rows are quarantined with their reasons, not just counted.
  • Owner and sensitivity metadata on every check, so governance travels with the rule. Published on PyPI under Apache-2.0.

03The result

3
engines, one check: pandas, DuckDB, warehouse SQL
1
definition per rule, with owner and sensitivity

TrueSet does the load reconciliation in the holdings project, proving what was loaded against what the SEC published, and the data contracts in the claims platform, where exactly the 40 broken rows are quarantined.
